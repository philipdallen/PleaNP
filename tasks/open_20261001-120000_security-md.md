## Finding

PleaNP has no `SECURITY.md`. Every other public repo in the portfolio has one (HuB, ephapse, rubato), so a reporter who finds a problem in PleaNP has no documented private channel and may open a public issue instead. The repo is Apache-2.0 with a `LICENSE` present, so the gap is the policy file, not the license.

## Evidence (verified against raw files)

- `PleaNP/SECURITY.md` does not exist (`ls` returns 'No such file').
- `HuB/SECURITY.md`, `ephapse` and `rubato` all ship one with the same shape: scope, supported versions, a private-report link, and expectations.
- The RLM security report names the missing policy as the primary documentation gap.

## Fix

Add `SECURITY.md` modelled on the sibling repos: scope (the Lean tree, the `tooling/` gates, the workflows), supported version (`main`), a private reporting route (GitHub private vulnerability reporting, plus an email fallback), and best-effort response expectations. Keep the email out of the tracked file if the owner prefers; the GitHub flow is enough.

## Verification

`PleaNP/SECURITY.md` exists; the reporting link resolves; the file names what is in and out of scope.

## Out of scope / do not re-derive

Do not add authn/authz, API, WAF, or SAST controls. PleaNP runs no service; the only deliverable is the policy file.
