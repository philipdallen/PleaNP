# DEC-028 — Consideration memo

**Decision:** RLM Analyzer triage decisions for PleaNP (see `docs/decisions/LOG.md` § DEC-028).
**Class:** Tier 1 — task protocol. It changes how findings become tasks, not how results are produced.

## 1. Direction restated

The owner asked that the findings from the RLM Analyzer pass be verified against
the repositories and turned into pickup-ready task files, with the governing
decisions logged before any task is created. This memo records the five decisions
(D1–D5) that govern that conversion, so each filed task cites a logged decision
rather than a chat message.

## 2. Why now

The RLM Analyzer reports are available for all five public repos. Filing tasks
directly from an LLM report would put unverified claims into the queue — the exact
failure mode the integrity gates exist to catch. These decisions are the gate
between report and queue, so they are logged before the first task is filed.

## 3. Conflicts

- **With the analyzer's confidence.** Several PleaNP findings are confidently
  stated and factually wrong for this repo (see § 7). D1/D2 resolve this: the
  report is a lead, not evidence.
- **With "file everything" convenience.** Filing all findings would inflate the
  queue with refuted items. D4 resolves this: only verified findings get a task.
- **With the security skill's generic checklist.** Its web-app controls
  (authn/authz, API validation, security headers, WAF, pen testing, SAST/DAST,
  log anomaly detection) assume a running service. PleaNP runs none, so D3 scopes
  them out rather than filing no-op tasks.
- **With existing trackers.** Some report items are already tracked (PleaNP #150
  and #152 for workflow hardening; #136 already fixed the `curl | sh`). D4's
  one-task-per-verified-finding rule avoids re-filing them.

## 4. Options

- **Option A (chosen).** Verify each finding against raw files; file one task per
  verified finding; record refuted findings in the summary. Log the decisions first.
- **Option B.** File every finding as a task and let workers re-verify. Rejected:
  it moves the triage cost into every future run and admits known-false items.
- **Option C.** File nothing and hand the report to the owner. Rejected: the owner
  asked for pickup-ready tasks, and verified findings are actionable without a
  human decision.

## 5. Reversibility

Fully reversible. The decision is a filing policy; it writes task files and one
DEC. Reverting means closing the tasks; no code, gate, or proof changes.

## 6. Falsifier

This decision is wrong if a filed task turns out to rest on a finding that raw-file
inspection does not support. That would mean D1's verification step was skipped or
done wrongly, and the task should be closed as invalid with the gap recorded.

## 7. Evidence

Verification was done by reading raw files in this repo, not by trusting the report.

- Confirmed: there is no `SECURITY.md` (`ls` returns not found), while HuB,
  ephapse and rubato each ship one. Filed as the one PleaNP task.
- Refuted: the report's `package.json` finding (no `package.json` exists), its
  `curl | sh` finding (`ci.yml` already calls the checksum-pinned
  `tooling/install_elan.sh`, fixed in #136), and its "no Lean/Mathlib pinning"
  finding (`lean/lean-toolchain` pins `v4.31.0`; both `lakefile.lean` files pin
  Mathlib `@ "v4.31.0"`).
- Already tracked, not re-filed: `ci.yml` `permissions:` (#150),
  `warm-toolchain.yml` `permissions:` (#152), `review-issue.yml` interpolation (#151).

## 8. Recommendation and open question

Recommendation: adopt Option A. Verify each RLM finding against raw files, file
one task per verified finding, and record refuted findings with their evidence.
For PleaNP the verified set is a single task (the missing `SECURITY.md`); the rest
of the report was either web-service advice that does not apply, claims already
fixed, or items already in the tracker.

`NEEDS: ratify DEC-028 (Tier 1 filing policy for the RLM triage pass).`

## 9. Run cap

Filing only. No code is changed. The work is bounded by the verified finding
count and completes within a single triage run.
